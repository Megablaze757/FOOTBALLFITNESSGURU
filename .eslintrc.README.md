# Why this config exists

`npm run lint` had **never run**. The script was `next lint` with no config, and
with no config `next lint` drops into an interactive setup prompt — so it hung in
CI and nobody got past it locally. Nothing in this repo had ever been linted.

The config is committed (rather than generated on first run) so the command is
non-interactive and the rule choices are reviewable. JSON has no comments, hence
this file.

## Rule choices

- **`react-hooks/rules-of-hooks: error`** — non-negotiable correctness.
- **`react-hooks/exhaustive-deps: warn`, not error.** There are deliberate
  single-run effects here with `eslint-disable` lines and a written reason: the
  meal planner restores a saved week on mount only, because re-running it on a
  stats change would silently rewrite the athlete's plan underneath them — and
  the shopping list they had already started buying against. Warn keeps those
  visible without failing the build on an intentional choice.
- **`@next/next/no-img-element: off`.** The app is `output: "export"`;
  `next/image` needs a loader we don't run and `images.unoptimized` is set
  deliberately in `next.config.mjs`. Warning about a rule we cannot follow is
  noise that trains people to ignore the linter.
- **`react/no-unescaped-entities: error`.** An unescaped apostrophe is a real
  rendering bug in user-facing copy, not a style preference.

`cloudflare/worker.js` is ignored: it is generated by esbuild, not written.
