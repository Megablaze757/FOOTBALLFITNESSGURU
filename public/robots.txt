# --- Answer engines ----------------------------------------------------------
#
# Named explicitly rather than left to the wildcard above. Two reasons: some of
# these read a named block and ignore "*", and being explicit is a decision on
# record rather than an accident of defaults.
#
# The bet: this is a new site with no brand searches, and being the source an
# assistant quotes is worth more than the click it might have sent instead.
# The public guides are the same coaching the app is built on — if a model
# quotes a heading drill and attributes it, that is the marketing.
#
# To reverse it, set Disallow: / under any of these.

# Everything below needs a session. Crawlers get a login redirect, not content,
# so indexing them wastes crawl budget and puts empty pages in the index.
Disallow: /home
Disallow: /journal
Disallow: /coach
Disallow: /nutrition
# NOT /recipes, /exercises, /collections or /cheapest-protein. Those are public
# pages built from the same data the app uses, with no session required — see
# app/recipes, app/exercises, app/collections and app/cheapest-protein.
# /library is the signed-in browser for the same catalogue and stays out.
Disallow: /library
Disallow: /essentials
Disallow: /squad
# ADDED AFTER THEY TURNED UP IN THE INDEXABLE SET.
#
# /ask, /injury and /partner sit in app/(app) like every route above and were
# simply missed off this list — which is not a small omission: a signed-in
# route exported statically is a five-word shell that inherits the ROOT
# title and description, so Google was free to index three empty pages
# competing with the homepage for its own name. Nothing on any screen would
# ever have shown that.
#
# The list is now derived from app/(app)/* by lib/robots.test.ts, so the next
# signed-in route cannot be forgotten the same way.
Disallow: /ask
